How it works

Architecture

Client

xml-language-client is the VS Code extension. It activates when VS Code opens a document with the xml language.

Server

wso2-mi-xml-ls is the language server. Build it with npm run bundle before running the client.

Expected path

The client starts the server from ../wso2-mi-xml-ls/dist/server.js.

Start here

Setup

Keep both repositories inside the same parent folder. The parent folder can have any name, but the server folder should be named wso2-mi-xml-ls. 

mkdir wso2-mi-xml-workspace
cd wso2-mi-xml-workspace

git clone https://github.com/harshanacz/wso2-mi-xml-ls.git
git clone https://github.com/harshanacz/xml-language-client.git

cd wso2-mi-xml-ls
npm install
npm run bundle

cd ../xml-language-client
npm install
npm run build
Important: npm run bundle must create wso2-mi-xml-ls/dist/server.js. The client depends on that file.

Development

Run in VS Code

  1. Open xml-language-client in VS Code.
  2. Run the Launch Extension debug configuration, or press F5.
  3. In the Extension Development Host window, open an .xml, .xsd, or .xsl file.
  4. The client starts ../wso2-mi-xml-ls/dist/server.js --stdio automatically.
Activation: The extension starts only after VS Code opens a document recognized as XML.

Fast fixes

Troubleshooting

Problem Check Fix
Server module cannot be found. ../wso2-mi-xml-ls/dist/server.js exists. Run npm install and npm run bundle in wso2-mi-xml-ls.
Extension opens but XML features do not work. An XML file is open in the Extension Development Host. Run npm run build in xml-language-client, then launch again.
The server repo has a different folder name. The client path still points to ../wso2-mi-xml-ls/dist/server.js. Rename the folder to wso2-mi-xml-ls, or update the path in src/extension.ts.
